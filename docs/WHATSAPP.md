# Native WhatsApp human delivery

The **Factuarea WhatsApp** action uses the genuine Factuarea API-key credential. It retains the existing signed trigger and CRM/OAuth node. Conversation operations currently declare no OAuth consent scope; the package does not create one. Use a dedicated live key with `account:read`, `conversations:write` for Prepare/Send and `conversations:read` for Original. Current native account, role, delegation, contact purpose consent, message fields, window and provider availability still govern every operation. External sandbox delivery is denied by the owner. No live delivery was used to verify this package.

Start from an existing authorized native WhatsApp conversation and draft message. **Prepare Human Review** calls the canonical `/crm/conversation/{conversation}/messages/{message}/whatsapp-cloud/preparation` GET. Provide only the native IDs, purpose and optional actual approved template selection. Sender, recipient, body, CAS, server-issued effect and sealed preparation token come from the owner. The output includes the complete `preview`, saved `prepared_whatsapp_json`, exact public seven-member `original_wire`, its SHA256 and `approval_snapshot_digest`. Save the complete output before any Send. Prepare does not send, claim or confirm a message.

Show the retained recipient, sender, body, purpose and template to the person making the decision. Use an explicit human approval step before **Send Approved Preparation**. Supply that saved JSON, set **A Person Approved This Exact Preview** only after this review and retain the digest belonging to that approved preview. The default is false. A mapped constant or an automatic Prepare-to-Send connection does not replace the human review.

Send checks the same current native API-key UUID and live realm, then revalidates the same preparation token. Changed body, participants, purpose, template, CAS, digest or native authorization revision blocks the POST. It never silently prepares a replacement. With **Retry On Fail** disabled, Send pins the actual stored native Bearer and sends exactly one raw original POST. Only the canonical owner receipt with `status: confirmed`, actual provider message identity and submission time permits continuation. A bare HTTP 200 does not confirm delivery. Continue On Fail returns a paired safe error and retains the original preparation for recovery.

For a timeout, denial or uncertain receipt, preserve the original and use **Read Original**. It sends only GET `/crm/conversation/{conversation}/messages/{message}/whatsapp-cloud/original` with the single `original_wire` query containing the exact saved public JSON bytes. This owner does not use the generic CRM Original digest query or Idempotency-Key header. It requires the same original native credential UUID; OAuth family ancestry is not a substitute. Confirmed recovery must match conversation, message, effect, exact wire hash and preparation digest, and preserves the canonical receipt. `not_found`, `unconfirmed` and `failed` never authorize another Send or another effect. Credential replacement or revocation requires native review, without re-preparing the uncertain message.

The package registers this as a separate version-1 action node, preserving the existing node and credential names. Its exported package was compiled and checked against the installed n8n SDK and native source pins; host installation, human approval integration, real account activation, webhook/Graph acknowledgement and public community verification remain deployment checks. A native provider ACK or HMAC is never manufactured from parsed workflow JSON. Prepared previews contain personal message data and the opaque native preparation token; apply normal host execution access and retention controls.
